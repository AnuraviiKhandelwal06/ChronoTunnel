# ChronoTunnel — Analytical Notebooks

This directory contains the exploratory data analysis (EDA), ridership investigations, statistical testing, and validation workflows supporting ChronoTunnel.

The notebooks provide a reproducible environment for examining NYC subway ridership patterns, validating analytical findings, and documenting insights before incorporating reusable logic into the main application.

## Notebook Structure

| Notebook | Purpose |
|---|---|
| `01_data_exploration.ipynb` | Dataset inspection, schema exploration, data quality assessment, missing-value and duplicate checks, and preliminary observations. |
| `02_ridership_analysis.ipynb` | Analysis of yearly and monthly trends, borough and transit-mode patterns, station-level demand, and hourly ridership patterns. |
| `03_statistical_analysis.ipynb` | Ridership distribution analysis, statistical testing, effect sizes, confidence intervals, and validation of analytical conclusions. |

## Execution Order

1. `01_data_exploration.ipynb` — Inspect datasets and assess data quality.
2. `02_ridership_analysis.ipynb` — Investigate ridership trends and demand patterns.
3. `03_statistical_analysis.ipynb` — Evaluate statistical evidence supporting selected findings.

## Dataset

The project uses the **MTA Subway Hourly Ridership dataset (2020–2024)**, published through NYC Open Data.

Processed datasets:

- `hourly_ridership_sample_station_level_2020_2024.csv`
- `monthly_ridership_station_level_2020_2024.csv`
- `station_coordinates.csv`

These datasets are maintained under `data/processed/`.

### Data Coverage and Interpretation

- The monthly dataset covers January 2020 through December 2024.
- The hourly dataset contains 120 selected dates: one Wednesday and one Saturday per month.
- Hourly findings describe this sample, not every day in the five-year period.
- Station coordinates represent analytical station-complex locations, not necessarily individual station entrances.
- Ridership and transfers are separate measures and must not be combined.

## Analytical Scope

- Yearly and monthly ridership trends.
- Weekday and weekend demand differences.
- Station-level ridership concentration.
- Borough-level ridership distribution.
- Transit-mode comparisons.
- Hourly demand and peak-hour concentration.
- Statistical validation of selected findings.

## Environment and Execution

Run commands from the repository root using the project virtual environment.

Install dependencies:

```powershell
python -m pip install -r requirements.txt
```

Launch Jupyter:

```powershell
jupyter notebook
```

Alternatively, open notebooks in Visual Studio Code and select the ChronoTunnel virtual environment as the kernel.

Execute cells from top to bottom.

## Notebook Conventions

1. Use notebooks for exploration, experimentation, and validation.
2. Keep reusable production logic in `src/chronotunnel/`.
3. Reuse existing analytical functions instead of duplicating calculations.
4. Document assumptions, sources, limitations, and observations.
5. Keep notebooks reproducible.
6. Avoid committing unnecessary large datasets or generated outputs.
7. Never modify original external datasets during exploratory analysis.
8. Statistical significance does not establish causation.
9. Preserve the distinction between sampled hourly data and the full monthly dataset.

## Relationship with the Main Application

The notebooks complement the ChronoTunnel data pipeline and Streamlit application.

Validated findings and reusable methods can be incorporated into `src/chronotunnel/`. The main application consumes analytical outputs generated by the project pipeline.
